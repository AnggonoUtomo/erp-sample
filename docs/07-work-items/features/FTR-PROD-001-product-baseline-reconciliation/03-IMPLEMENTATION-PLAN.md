## Urutan

1. Ganti Product Brief dengan identitas dan outcome produk yang disetujui.
2. Susun PRD berbasis capability stabil.
3. Tetapkan klasifikasi scope tanpa fase atau jadwal.
4. Turunkan capability menjadi FR, NFR, dan aturan bisnis yang dapat diuji.
5. Bangun traceability outcome/capability/requirement/bukti.
6. Jalankan pemeriksaan istilah konflik, metadata, link, heading, code fence, scope Git, dan inventory.
7. Lengkapi review, evidence, completion, backlog, registry, serta status task.

## Area Perubahan

Hanya dokumentasi yang tercantum pada `TASKS.md`. Tidak ada rollout aplikasi atau migration.

## Rollback

Revert atomik commit dokumentasi bila baseline ditolak. Dokumen historis tetap tersedia melalui Git dan `docs/11-baselines`.

## Keterlacakan

`PLAN.md` dan `TASKS.md` adalah kontrol eksekusi kanonis.
